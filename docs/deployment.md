## The project settings

The app is an ordinary Next.js build, so any host that runs Node 24 serves it. This repository is deployed on
Vercel with these settings, and they are the whole configuration: there is no `vercel.json`.

| Setting          | Value                            | Why                                                                                                        |
| ---------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Framework preset | Next.js                          | Detected from `apps/web`                                                                                   |
| Root Directory   | `apps/web`                       | The app, not the repository root. The install still runs across the workspace, because the lockfile is one |
| Install command  | `pnpm install --frozen-lockfile` | The default is `pnpm install`, which is frozen only because the host sets `CI`. Saying it is cheaper       |
| Build command    | Inherited                        | The preset detects Turborepo and runs `cd ../.. && turbo run build --filter={apps/web}...`                 |
| Node.js version  | 24.x                             | A host offers majors only; `engines.node` in every `package.json` pins the floor                           |
| Git integration  | Not connected                    | A template is copied, not followed: a deploy on every push belongs to the copy, not here                   |

## The environment variables

One, in Production and in Preview:

| Variable               | Value                       | What breaks without it                                                                              |
| ---------------------- | --------------------------- | --------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL` | The public origin it serves | Absolute URLs fall back to `http://localhost:3000`, which is what Open Graph images resolve against |

Development needs nothing: the schema in [`@repo/env`](../packages/env/README.md) defaults every variable to a
value that works on a laptop, which is why `pnpm dev` runs on a fresh clone with no `.env` file at all.

## What the build ran

From the build log of a production deployment, with the install command asked to print its own versions:

```text
Detected `pnpm-lock.yaml` version 9 generated by pnpm@11.x from package.json#packageManager pnpm@11.17.0
Running "install" command: `node -v && corepack --version && pnpm install --frozen-lockfile`...
v24.19.0
0.34.5
Scope: all 13 workspace projects
Done in 970ms using pnpm v11.17.0
Detected Next.js version: 16.3.5
Running "cd ../.. && turbo run build --filter={apps/web}..."
```

So the container runs a Node 24 above the floor `engines.node` sets, and the pnpm that `packageManager` names
rather than the host's own default. Both are worth reading on the first deployment of a fork: `engineStrict`
in [`pnpm-workspace.yaml`](../pnpm-workspace.yaml) turns a wrong Node into a failed install rather than a
build that quietly used it.

## Deploying from the command line

```bash
pnpm dlx vercel@latest link       # once per clone, writes the git-ignored .vercel/
pnpm dlx vercel@latest deploy --prod
pnpm dlx vercel@latest inspect --logs <deployment-url>
```

`pnpm build` is the same build the host runs, so a failure there is a failure at the host too.

## Traps

- **Corepack is a dead end here.** `ENABLE_EXPERIMENTAL_COREPACK=1` is the documented way to make a host obey
  `packageManager`, and Vercel reads it, then disables corepack again unless `COREPACK_HOME` is in
  `turbo.json#globalPassThroughEnv`. It is also unnecessary: the platform reads `packageManager` itself and
  installs with pnpm 11.17.0 without it. Setting it only adds two warnings to every build, one of them
  claiming a variable will be missing from the app.
- **Only majors.** A host picks the latest patch of the major it offers, so the exact Node of a build is not
  yours to pin. `engines.node` pins the floor and `engineStrict` enforces it.
- **`vercel link` writes to `.gitignore`.** It appends `.vercel` even though the file already ignores
  `.vercel/`. Drop the duplicate line rather than committing it.
- **The CLI expires.** A Vercel CLI older than 47.2.2 is refused by the deployment endpoint, which is why the
  commands above pin nothing and fetch the current one.
- **The URL in a copy.** This document names the deployment of the template itself. A repository created from
  it deploys somewhere else, and [`CONTRIBUTING.md`](../CONTRIBUTING.md#the-name-in-the-tree) lists this file
  among the places that still carry the template's name.

This template is deployed at <https://nextjs-starter-kit-orcin.vercel.app>.
